# 《明日方舟》MVU 主线沙盒自动衔接规范 v1.0

> 本文件只定义主线 MAIN-00～MAIN-17 的“进入沙盒后自动切下一卷”。
> SideStory 默认禁用自动串联。

## 1. 目标

主线每卷最后都有 `沙盒模式`。当咩咩状态明确表明当前主线卷已进入该沙盒时，MVU 自动把世界书切到下一主线卷，实现无缝衔接。

- MAIN-00 -> MAIN-01
- MAIN-01 -> MAIN-02
- ...
- MAIN-16 -> MAIN-17
- MAIN-17 -> 不再切卷，进入主线最终沙盒

## 2. 触发条件

自动切换必须同时满足：

1. 当前唯一 enabled 时间线条目属于 `MAIN-*`；
2. 咩咩 `<status>` / 世界运行报告明确出现当前剧情状态为 `沙盒模式`（或等价的已完成本卷标志）；
3. 该沙盒状态属于当前 active volume，而不是历史消息；
4. 当前卷不是 `MAIN-17`；
5. 本轮尚未对该 active volume 执行过自动衔接。

禁止仅凭“长时间没事件”“日期超过某值”“玩家没操作”等模糊条件自动切卷。

## 3. 切换事务

触发后直接复用成熟卷切换事务：

1. 读取 `manifest/mvu-timeline-switch.v1.json`；
2. 在内存把 73 条 `ARKNIGHTS_TIMELINE:*` 全部置为 disabled；
3. 只启用 `next_main` 对应 marker；
4. 一次性写回；
5. 写回成功后刷新 ACTIVE 与封面；
6. 写回失败则保留旧卷，不伪装成功。

自动衔接只是触发来源变化，底层事务不得另写一套。

## 4. 时间衔接

进入下一主线卷后：

- 不继承上一卷沙盒中的任意虚构日期；
- 直接以新卷事件A/A1中已经核定的时间锚点作为下一段剧情时间；
- 若新卷首事件只提供相对时间，则由咩咩按该卷前置规则推进；
- 不让沙盒无限时间覆盖下一卷正式事件。

## 5. SideStory 策略

55 个 SideStory **默认全部禁用自动下一卷**。

理由：SideStory 并不是按 manifest 列表组成的一条连续时间线；其中包含：

- 发生在不同年份的独立事件；
- 穿插在主线之间的事件；
- 多时间层/回忆事件；
- 同一系列但相隔数月或数年的事件。

因此 SideStory 沙盒结束后：

- 保持当前 SideStory enabled；
- MVU 显示 `SANDBOX / 本卷自由行动`；
- 玩家手动进入 OPERATIONS 选择下一卷；
- 不根据数组顺序自动切到下一 SideStory。

后续若另建经过来源审计的 `side chronology map`，也只能作为推荐阅读顺序；除非单独批准，不自动写世界书。

## 6. MAIN-17 最终状态

`MAIN-17` 进入沙盒后：

- 不再自动切卷；
- 保持 MAIN-17 为唯一 enabled；
- MVU 显示 `MAIN STORY COMPLETE / SANDBOX`；
- 玩家可继续自由行动或手动进入任一 SideStory/其他卷。

## 7. QA

- [ ] MAIN-00～MAIN-16 每卷进入沙盒只触发一次 next_main；
- [ ] 自动切换后恰好 1/73 enabled；
- [ ] 新卷 ACTIVE 与世界书真实状态一致；
- [ ] 写入失败时不更新 UI；
- [ ] 历史楼层中的“沙盒模式”不会触发；
- [ ] SideStory 沙盒绝不自动切下一卷；
- [ ] MAIN-17 沙盒不自动切卷；
- [ ] 自动切换复用成熟事务，不新增第二套 `_current_volume`。
