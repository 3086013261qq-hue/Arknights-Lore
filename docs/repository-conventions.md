# 仓库施工规范 v1.1

## 1. 仓库职责

`Arknights-Lore` 只作为《明日方舟》咩咩全栈角色卡的远程剧情时间线资源层。

远程内容仅包括：
- 主线剧情时间线
- 活动与支线剧情时间线
- 角色个人剧情时间线（仅事件链）
- 剧情 manifest 与远程加载协议

角色、地点、核心设定全部保留在卡内世界书，不从本仓库远程加载。

## 2. 目录职责

- `manifest/`：剧情资源索引，只保存轻量元数据、剧情块顺序与文件映射。
- `timeline/main/`：主线剧情时间线。
- `timeline/side/`：活动与支线剧情时间线。
- `timeline/operator/`：角色个人剧情时间线。
- `runtime/`：远程剧情加载协议、路径规则与卡侧桥接约定。
- `docs/`：施工单、来源策略、映射与版本说明。
- `QA/`：剧情查漏、冲突、重复与验收记录。

## 3. 时间线拆分

- 禁止把整部主线或整个大型活动塞进单个超大文件。
- 时间线按可独立加载的剧情块拆分，每块必须有稳定 ID。
- 每个剧情块保留时间、地点、事件顺序、人物关键动作、因果、结果、状态变化与必要前后置。
- 不保留大段原作对白；仅在剧情辨识确有必要时保留极短关键句。
- 相邻块不重复大段内容；上一块结果通过轻量状态摘要衔接。

## 4. 标识与版本

- 文件名使用稳定 ASCII slug；中文篇章名保存在文件内容和 manifest 中。
- manifest schema 与剧情内容版本分离。
- 已发布路径尽量保持稳定；破坏性结构变更必须升级 manifest 主版本。

## 5. 远程加载

运行时优先：
1. 读取 `manifest/story-index.v1.json`；
2. 根据当前剧情状态确定唯一合法剧情块；
3. 仅加载当前剧情块，必要时附带极短上一状态摘要；
4. 不预载整部主线、全部活动或角色/地点/设定资料。

咩咩预设仍负责正文生成；MVU仅负责展示与轻交互，不是剧情唯一事实源。

## 6. 提交原则

- 原始参考资料不提交到公开仓库。
- 正式剧情必须重新组织、压缩和改写。
- 剧情重写、索引更新、运行时修改尽量拆分提交，便于回滚与审计。
- 每批正式剧情完成后补对应 QA 记录。
