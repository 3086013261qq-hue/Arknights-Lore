# 仓库施工规范 v2.0

## 1. 仓库职责

`Arknights-Lore` 现同时承担四类资产：
1. 可持续返修的正式角色世界书源稿；
2. 剧情时间线远程资源与运行时索引；
3. MVU干员媒体；
4. 构建、参考、QA与施工文档。

四层职责必须分离，禁止因为修改角色而重建时间线或媒体。

## 2. 目录职责

- `worldbook/operators/`：正式干员角色正文与同名能力条目；一人一文件，是后续角色返修的唯一正式源。
- `build/character-worldbook/`：批次施工、样板、QA、冲突与装配记录；不是长期正文事实源。
- `manifest/operator-worldbook.v1.json`：角色正式源索引与精修状态。
- `media/mvu/operators/`：封版媒体；每人 `elite1.png` + `idle.gif`。
- `manifest/operator-media.v1.json`：媒体索引。
- `timeline/main/`：主线时间线。
- `timeline/side/`：SideStory时间线。
- `timeline/operator/`：角色个人剧情事件链。
- `runtime/`：剧情远程加载协议、路径规则与卡侧桥接约定。
- `manifest/`：稳定索引层。
- `docs/`：施工单、来源策略、映射与版本说明。
- `QA/`：全局查漏、冲突、重复与验收记录。
- `reference/`：轻量参考索引；不得作为正式正文直接镜像。
- `tools/`：离线抓取、构建和验证工具。

## 3. 角色世界书维护

- 角色粗卡用于批量打底，精修后直接进入 `worldbook/operators/<干员名>.md`。
- 每个正式文件同时保留人物条目与同名能力条目。
- 后续返修直接读取正式角色文件；不要求回到原始粗卡或历史 Batch。
- Batch 每 50 人仅用于进度与QA管理，内部可按10人小组处理。
- 三句对话范例在主体精修阶段保持原样。
- 萌点在全部463名主体精修完成后单独逐一补充。
- 角色精修可以读取已封版 Elite1 PNG / idle GIF 做视觉核对，但不得因此重新设计媒体流水线。

## 4. 时间线维护

- 时间线按可独立加载剧情块拆分，每块保留稳定 ID。
- 主线与 SideStory 已封版；除明确硬错误外，不做文学式返工。
- 不把角色正文塞进远程时间线运行层。

## 5. 媒体维护

- 正式媒体路径固定为：
  - `media/mvu/operators/<干员名>/elite1.png`
  - `media/mvu/operators/<干员名>/idle.gif`
- 媒体 manifest、文件名与目录结构已封版。
- 角色精修阶段不得重新抓取、生成、重命名或改造媒体流水线。

## 6. 提交原则

- 角色批次：精修正文 + 必要QA/manifest更新可作为一个原子提交。
- 单人返修：只修改该角色正式文件与必要索引，不重做整个批次。
- 时间线、角色、媒体尽量保持独立提交，便于回滚和审计。
- 不修改咩咩预设。
