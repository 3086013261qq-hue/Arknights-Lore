# 仓库施工规范 v1.0

## 1. 目录职责

- `manifest/`：资源索引，只保存轻量元数据与文件映射。
- `timeline/`：按主线、支线/活动、角色个人剧情分区。
- `characters/`：正式角色资料。
- `locations/`：正式地点资料。
- `settings/`：核心设定资料。
- `runtime/`：远程加载协议、路径规则与卡侧桥接约定。
- `docs/`：施工单、规范、映射与版本说明。
- `QA/`：查漏、冲突、重复与验收记录。

## 2. 文件拆分

- 禁止把整部主线或整个大型活动塞进单个超大文件。
- 时间线按可独立加载的剧情块拆分；每块必须有稳定 ID。
- 每个剧情块只描述事件事实、顺序、关键动作、结果与状态变化，不保留大段原作对白。
- 角色、地点、设定文件应可独立加载，避免跨文件隐式依赖。

## 3. 标识与版本

- 文件名使用稳定 ASCII slug；中文名称保存在文件内容中。
- manifest schema 与资料内容版本分离。
- 已发布路径尽量保持稳定；破坏性结构变更必须升级 manifest 主版本。

## 4. 远程加载

- 运行时优先读取 manifest，再按当前篇章、地点、角色动态加载对应资源。
- 卡本体只保留最小常驻设定、当前状态与远程索引。
- MVU只负责展示与轻交互，不承担唯一剧情事实源职责。

## 5. 提交原则

- 原始参考资料不提交到公开仓库。
- 资料重写、索引更新、运行时修改尽量拆分提交，便于回滚与审计。
- 每批正式资料完成后必须补对应 QA 记录。
