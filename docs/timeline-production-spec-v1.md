# 明日方舟剧情时间线生产规范 v1.1

> 目标：用 PRTS 已结构化的剧情简介节点直接生成咩咩全栈可用的 `<world_timeline>` 母稿；再用《明日方舟剧本小说》补日期与相邻时序，最后人工精修与 QA。
> 适配：咩咩制卡包·全栈与现有咩咩预设；禁止修改预设本体。

## 1. 核心路线

不再让 AI 从整章剧情重新拆事件。

正式流水线：

1. PRTS 源码中的 `{{剧情简介|关卡编号|关卡名称|剧情类型|剧情简介}}` 作为事件节点主来源。
2. 同一关卡编号自动归为同一事件组：行动前=A，行动后/幕间=A1/A2；下一关=B/B1……。
3. 《明日方舟剧本小说》只用于日期、时段、相邻节点时间差与回溯/当前时序校对，不复制小说正文。
4. PRTS 泰拉年表与官方明确日期用于最终时间 QA；冲突时以官方/PRTS 为准。
5. 生成咩咩原生 `<world_timeline>` 母稿，再进行人工精修、查漏与压缩。

## 2. 冻结输出格式

每章一个完整块，卷名/篇章名不写入标签内部：

```text
<world_timeline>
-事件A: 0-1《坍塌》·行动前 (1096年12月23日): 事件摘要
-事件A1: 0-1《坍塌》·行动后 (同日): 事件摘要
-事件B: 0-2《守卫》·行动前 (随后): 事件摘要
...
-事件X: 沙盒模式 (接续上一事件时间起 - ∞): 当前章节既有事实保持有效；进入下一正式剧情块时按其前置继续。
</world_timeline>
```

规则：
- 每章从事件 A 开始。
- 独立关卡/独立剧情节点用 A/B/C 顺延。
- 同一关卡连续阶段用 A1/A2/A3。
- 事件正文固定为 `标题 (时间锚点): 描述`。
- 时间未核实则写 `时间待核`，禁止编造日期。
- 最终精修时可把同一节点摘要进一步压缩成 `锚点·锚点·锚点`，但不得改变事实顺序。

## 3. 数据来源职责

### PRTS 剧情简介源码
负责：
- 关卡编号
- 关卡名称
- 行动前/行动后/幕间等剧情类型
- 节点摘要
- 节点原始顺序

### 《明日方舟剧本小说》
负责辅助：
- 年月日
- 时段
- 相邻节点间隔
- 同日/次日/数小时后等相对时间
- 回忆、历史片段与当前时序区分

不得将小说化扩写、心理补写或非官方描写写成硬事实。

### PRTS 泰拉年表/官方明确时间
负责最终校准高置信日期与时刻。

## 4. 存储策略

先同时生成：
- 每章独立时间线块；
- 合并后的卡内世界书版本；
- provenance / date-candidates / missing-dates QA；
- 实际字节体积报告。

是否远程加载不预设。若整套精修时间线体积可控，则直接保留在卡内世界书；MVU 只负责展示与轻交互。PNG/GIF 等视觉媒体可独立走远程媒体层。

## 5. 第一阶段验收

先只生成主线 00–01：
- `main-00 黑暗时代·上`
- `main-01 黑暗时代·下`

验收：
1. PRTS 剧情简介节点是否完整抓取。
2. 同关卡是否正确映射为 A/A1/A2。
3. 节点顺序是否与 PRTS 一致。
4. 小说日期匹配是否只作为候选，不误填。
5. 无日期时是否保留 `时间待核`。
6. 输出是否可直接作为咩咩世界书条目继续精修。
7. 统计 00–01 及预计全主线体积，再决定卡内/远程策略。

## 6. 扩展范围

00–01 通过后再扩展：
- 主线 00–17；
- PRTS 情报处理室中的 SideStory；
- 微型故事集/故事集；
- 必要的角色个人剧情事件链。

只要 PRTS 页面使用同类 `剧情简介` 模板，优先复用同一 parser，不再重复手工拆节点。
