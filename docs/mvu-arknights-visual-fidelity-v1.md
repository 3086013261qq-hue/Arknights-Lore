# 《明日方舟》MVU 原版视觉高保真补充规范 v1.0

> 本文件是 `docs/mvu-final-ui-spec-v1.md` 的视觉层补充规范。
> **视觉与音乐部分发生冲突时，以本文件为高优先级；业务、状态、世界书规则仍以原最终规范为准。**
> 目标不是“黑底黄字的明日方舟风”，而是让成品在第一眼就明确属于《明日方舟》/ 罗德岛 / PRTS 的界面体系。

## 1. 最重要的验收原则

以下做法 **一律不算完成**：

- 黑色背景 + 黄色边框 + 四个普通按钮；
- 把页面做成通用后台 Dashboard；
- 大量等宽圆角卡片整齐平铺；
- 只有文字与边框，没有视觉主次与大面积角色/章节图像；
- 紫蓝霓虹、玻璃拟态、发光描边、赛博朋克 HUD；
- 用 Material / iOS / Bootstrap 默认组件稍改颜色冒充《明日方舟》；
- 页面过空、过素、像开发者测试页。

**硬性验收：隐藏标题文字后，仅看构图、层级、斜切、色块、信息密度与图像使用，也必须能判断这是《明日方舟》式终端界面。**

## 2. 原版视觉语法必须同时出现

每个主页面都要组合使用，而不是只取其中一种：

1. **强非对称构图**：大图与信息块左右/上下错位，不做平均宫格。
2. **大面积黑白灰 + 小面积高纯度黄**：黄色只用于 ACTIVE、主按钮、焦点、警示标记，不铺满。
3. **硬边与斜切**：0～2px 圆角；用 `clip-path`、伪元素、斜杠、缺角、短横线制造原版工业感。
4. **英文字段 + 中文信息并置**：大写英文模块名、编号、微字、中文正文形成层级差。
5. **大号编号/序号**：如 `01 / 04`、`MAIN 08`、`OPERATOR 032`，可低透明度压在背景层。
6. **细密信息条**：状态码、位置、TIME、ARCHIVE、ONLINE 等作为装饰性信息层，但不得伪造剧情事实。
7. **图像强参与构图**：章节封面、干员立绘必须成为页面视觉主体，而不是缩成小头像。
8. **明显前后景层级**：背景纹理/编号层 → 主视觉层 → 信息面板层 → 操作控件层。
9. **短促干净的动效**：120～180ms；位移、切片、淡入；不要弹性果冻、漂浮粒子、炫光。
10. **工业化留白**：留白是为视觉方向服务，不允许大块无意义空白。

## 3. CSS 美化要求

允许并鼓励使用 CSS 生成视觉装饰，避免直接复制游戏 UI 壳素材：

- `linear-gradient` / `repeating-linear-gradient` 生成网格、扫描线、警戒斜纹；
- `clip-path: polygon(...)` 生成斜切卡片和按钮；
- `::before` / `::after` 生成模块编号、短线、角标、黄黑警戒条；
- 低透明度超大数字作为背景层；
- 1px 硬线 + 2～4px 局部粗线形成层级；
- `mix-blend-mode` 仅轻量使用，不能牺牲可读性；
- 阴影应硬、短、克制，禁止柔软大光晕。

不得打包《明日方舟》专有字体；使用系统无衬线字体，通过字重、字距、大小写和数字排版实现相近视觉语言。

## 4. 四页必须分别有自己的“原版感构图”

### TERMINAL / 终端

- 当前行动封面作为首页最大视觉块，允许裁切，不要完整缩小塞进卡片。
- 一侧叠加 `<status>` 的时间、地点、阶段、任务；另一侧用大号 `P.R.T.S.` / 卷编号形成背景层。
- 四个入口不是四张一样的方卡：使用一大两中一窄的非对称模块组合。
- ACTIVE 行动使用黄色窄条/角标，而不是整块黄色背景。

### OPERATIONS ARCHIVE / 作战档案

- 当前卷卡占主视觉 60% 左右，左右邻卷只露出边缘，形成原版章节选择的“横向档案带”。
- 封面上叠加卷编号、中文标题、MAIN / SIDE STORY、ACTIVE 状态。
- `ENTER / 进入记录` 必须是全页最醒目的操作控件，使用黄底黑字或黑底黄切边的原版式主按钮。
- MAIN / SIDE STORY 切换做硬标签或切片，不做圆角胶囊。

### OPERATOR RECORDS / 干员档案

- `elite1.png` 必须占详情页约 45%～60% 的视觉面积，允许角色越界裁切。
- 信息层采用原版人事档案感：大号编号、代号、PROFILE / ARMAMENT / STATUS 硬切标签。
- `idle.gif` 仅点击 DYNAMIC 后替换主视觉；未点击前不请求。
- 列表页避免“463 个头像小方格全部铺满”，优先使用搜索 + 紧凑列表 + 选中详情。

### TERRA ARCHIVE / 泰拉档案

- 使用“资料索引 / 情报终端”构图：左侧或顶部大类编号，右侧条目列表与详情。
- CORE / LOCATIONS / NPC 使用明显编号与硬切换条，不做普通 Tabs。
- 条目详情要有标题层、元信息层、正文层，不允许一大段纯文本直接贴在黑底上。

## 5. 资源与纹理

- 已有章节封面、干员 PNG/GIF 可以直接作为主视觉素材。
- 不需要再寻找一套“UI 背景图包”。
- 背景纹理、斜纹、编号、分隔线优先用 CSS 生成。
- 禁止 Base64；禁止把官方游戏 UI 截图整张当背景壳。
- 允许使用仓库中已经审计并服务于本卡的媒体资源。

## 6. 移动端美化不许降级成简陋版

360px 宽度下也必须保留：

- 斜切与模块编号；
- 大图裁切；
- ACTIVE 黄强调；
- 英文微字层；
- 前后景层次；
- 非对称布局。

只能缩放/重排，不能因为手机端就退化成“标题 + 四个矩形按钮”。

## 7. 视觉 QA 硬门槛

静静必须至少输出并检查以下实机截图：

- 360px：TERMINAL 首页；
- 360px：OPERATIONS 当前卷；
- 360px：OPERATOR 单人详情；
- 560px：TERMINAL 或 OPERATIONS 宽屏状态。

每张截图逐项 PASS：

- [ ] 第一眼属于《明日方舟》/ PRTS 视觉体系，而非通用赛博 UI；
- [ ] 有明确主视觉，不是纯文字面板；
- [ ] 有至少三层视觉层级；
- [ ] 有斜切/硬边/编号/英文微字；
- [ ] 黄色只用于重点；
- [ ] 无大圆角、玻璃拟态、霓虹光晕；
- [ ] 信息密度足够但不拥挤；
- [ ] 手机端没有退化成简陋版；
- [ ] 所有文字可读、按钮可点；
- [ ] 不影响咩咩状态与世界书业务逻辑。

**只要“像开发者原型页”或“换色后的普通网页”，视觉 QA 直接 FAIL，必须返工后才能出正式 PNG/JSON。**
