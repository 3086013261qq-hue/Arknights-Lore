# 明日方舟多源富粗卡流水线 v2.6

## 目标

把角色资料采集、立绘采集、视觉识别和粗卡填充放进同一条电脑本地流水线，尽可能把人工工作压缩到“核对 + 精修”。

## 三层结构

### A. 原始采集层（仅本地，不提交）

```text
raw-source/
├─ prts/<角色名>/
│  ├─ source.html
│  ├─ parsed.json
│  └─ metadata.json
├─ moegirl/<角色名>/
│  ├─ source.html
│  ├─ fields.json
│  └─ metadata.json
├─ artwork/<角色名>/
│  ├─ default.*
│  ├─ elite2.*
│  └─ metadata.json
└─ vision/<角色名>.json
```

规则：
- 原始网页、萌百原字段、图片、视觉模型原始输出全部保留。
- 这一层只作为本地审计与后续重跑依据。
- 默认由 `.gitignore` 排除，不进入公开仓库。

### B. 来源合并层

程序生成 `build/rough-worldbook/provenance/<角色名>.json`，逐字段记录：

```json
{
  "发色": {"value":"...","source":"moegirl:发色","confidence":1.0},
  "上衣": {"value":"...","source":"vision:elite2","confidence":0.83}
}
```

来源优先级：

1. PRTS/官方明确事实：身份、种族、所属、出身、感染情况、经历、能力等。
2. 萌娘百科原字段：字段名和字段值原样保留；若与咩咩目标字段同名，可直接作为候选值，但不得改写原字段。
3. 视觉识别：只补视觉字段空缺，不覆盖已有明确文字字段。
4. 冲突不自动选边，写入 QA。

### C. 粗卡成品层

目标字段：

```text
名字
性别
种族
身份
所属
出身
感染情况
印象
发色
发型
瞳色
身材
胸部
上衣
下装
配饰
鞋子
经历
关系
心理模型
对话范例
能力
```

自动填充范围：
- PRTS：基础档案、经历、特性、天赋、技能、能力线索。
- 萌百：保留全部短原字段；目标字段同名时可直接引用。
- 立绘视觉：发色、发型、瞳色、身材观感、上衣、下装、配饰、鞋子、耳/角/尾/武器等。

不得自动生成的内容：
- 精确罩杯数值。
- 没有来源支持的年龄、体重、三围。
- 性格心理的硬事实化判断。
- 与文字来源冲突时的自动覆盖。

## 视觉识别规则

视觉模型必须按结构化 JSON 输出，不允许只给自然语言长描述：

```json
{
  "发色": {"value":"", "confidence":0.0},
  "发型": {"value":"", "confidence":0.0},
  "瞳色": {"value":"", "confidence":0.0},
  "身材": {"value":"", "confidence":0.0},
  "胸部": {"value":"", "confidence":0.0},
  "上衣": {"value":"", "confidence":0.0},
  "下装": {"value":"", "confidence":0.0},
  "配饰": {"value":"", "confidence":0.0},
  "鞋子": {"value":"", "confidence":0.0},
  "明显生理特征": [],
  "武器": []
}
```

视觉字段规则：
- 只描述画面可见内容。
- 不推断身份、年龄、种族等非纯视觉事实。
- `胸部`只允许平坦/纤细/匀称/丰满/非常丰满等粗粒度描述，不猜具体罩杯。
- 默认优先读取基础立绘，精二立绘用于补充；有冲突时保留两份结果并进入 QA。

## 双源文字原则

萌百原字段必须独立保存，例如：

```text
<原始资料:角色名·萌娘百科>
来源页面:...
原字段:
发色:...
瞳色:...
身高:...
萌点:...
...
</原始资料:角色名·萌娘百科>
```

禁止做以下自动映射：
- `萌点:单马尾` → `发型:单马尾`
- `萌点:巨乳` → `胸部:丰满`
- `萌点:长靴` → `鞋子:长靴`

只有原字段名与目标字段名完全一致时，才允许直接作为候选值写入 provenance。

## QA

每个角色至少生成：
- `source-status.json`
- `provenance.json`
- `conflicts.json`
- `vision.json`

全量 QA 要统计：
- PRTS 抓取失败数
- 萌百匹配失败数
- 立绘下载失败数
- 视觉识别失败数
- 字段冲突数
- 仍为待精修的字段数

## 运行原则

- 默认先 5 人测试，再全量。
- 原始层与视觉缓存全部放在仓库所在磁盘，不使用 C 盘默认缓存。
- 图片和原始网页不进入远程运行时。
- 正式卡内仍只放精修后的角色、地点、设定；剧情时间线继续走远程层。
