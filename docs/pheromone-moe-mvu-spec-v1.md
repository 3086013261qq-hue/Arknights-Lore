# 《明日方舟》独立卡 费洛蒙 / 气味签名系统设计规范 v1.0

> 本文件只定义原创 AU 的“费洛蒙 / 气味签名”表现层与 MVU 展示方式。
> **它不是《明日方舟》原作事实，不覆盖原作种族、生理、关系或人格。**
> 最终由静静按本规范批量装配进现有萌点 overlay，并生成轻量 MVU 索引；不新建第二套角色状态机。

## 0. 目标

覆盖：

- 463 / 463 干员；
- 全部核心 NPC；
- 博士独立 NPC 条目补入后也必须纳入；
- 机械 / 自律装置 / 非传统生物同样拥有“可辨识气味签名”，但不得硬写成生物费洛蒙。

每个角色都必须拥有**独立且能被辨认的气味签名**，避免批量生成成“同种族一模一样”。

本系统服务三件事：

1. 把角色种族与个体气质转成可感知的“萌点”；
2. 允许剧情出现动物式、群体式的亲密社交行为；
3. 在 MVU 中提供只读 `PHEROMONE / SCENT ARCHIVE` 气味档案。

---

# 1. 数据必须直接并入“萌点”

## 1.1 干员

现有：

- `worldbook/operator-moe.v1.json`
- `worldbook/operator-moe/batch-*.json`

继续作为唯一萌点 overlay。

每名干员的最终 `moe` 需要在现有兽化 / 非人体征之后增加一段简短气味描述，例如结构上表现为：

`原萌点。气味签名: 冷杉针叶、雨后石面与极淡的金属气息；情绪紧绷时会多出辛冷味。亲近习惯: 熟悉后更倾向先嗅闻确认，再用肩/耳/尾部轻蹭留下气味。`

**不要修改 canonical operator body 来承载这段内容。**
最终组装时仍由萌点 overlay 合并进角色正文。

## 1.2 NPC

NPC同样采用轻量 overlay，不污染原作角色正文。

静静需生成：

`worldbook/npc-moe.v1.json`

结构与 operator moe 对齐，并在最终世界书材料化时合并至对应 NPC 角色条目。

博士补为独立 NPC 后，NPC target count 随之更新，并必须拥有自己的气味签名。

# 2. 每个角色的独立气味签名格式

每条数据最少包含：

- `name`
- `signature_type`: `biological` / `mechanical` / `special`
- `base_notes`: 2～4 个短气味意象
- `intensity`: `very-low` / `low` / `medium` / `high`
- `emotion_shift`: 情绪变化时的气味倾向
- `social_marking_style`: 该角色最自然的动物式/群体式亲近动作
- `boundary_class`: `adult-consensual` / `nonsexual-only`
- `moe_append`: 最终并入萌点的一到两句中文

### 2.1 个体化来源优先级

生成独立气味时依次参考：

1. 角色已有 canonical 正文中的种族与生理特征；
2. 已封版萌点中的兽耳 / 角 / 尾 / 羽毛 / 鳞片 / 机械特征；
3. 职业与长期环境（医疗、工坊、荒漠、雪原、航海、火药等）；
4. 角色稳定人格气质；
5. 官方形象中的长期辨识意象。

不得从“名字听起来像什么”直接编种族或身体特征。

### 2.2 同种族也必须区分

例如同为鲁珀：

- 德克萨斯不能和拉普兰德、伺夜拥有完全相同的气味；
- 种族只提供底层生物倾向，个体气味必须由职业、环境、人格再区分。

禁止批量模板：

`鲁珀 = 松木 + 皮革`

然后所有鲁珀复制粘贴。

---

# 3. 非生物角色处理

机械 / 作业平台 / 自律装置不写“生物费洛蒙腺体”。

统一使用：

`signature_type: mechanical`

可使用：

- 机油
- 热金属
- 冷却液
- 绝缘材料
- 电离空气 / 臭氧
- 消毒剂
- 设备维护剂

作为“气味签名”。

其社会标记可表现为：

- 允许熟悉对象靠近机体；
- 通过维护用品、外壳接触留下熟悉气味；
- 主动调整机体距离 / 发热 / 提示音作为亲近表现。

禁止为了统一格式硬写兽类舔舐或生物激素。

---

# 4. 动物式社交标记规则

这里的“标记”定位为**动物式社交亲近与群体识别**，不是魔法控制，也不是强制配偶绑定。

在人物关系允许时，可以自然出现：

- 靠近后先嗅闻确认熟悉气味；
- 用脸颊、额头、肩膀、耳侧、尾巴或衣物轻蹭；
- 抱住后把自己的气味留在对方衣物 / 发丝上；
- 交换围巾、外套、枕头、毛毯等带有气味的物件；
- 同伴受惊时贴近嗅闻、轻蹭，用熟悉气味安抚；
- 兽化特征明显的角色可进行梳毛、理羽、整理耳尾等群体 grooming；
- **明确成年且双方愿意的亲密关系中**，可出现非露骨的梳理式舔舐，例如舔一下发丝、耳尖、脸颊或手背，作为动物式亲昵动作。

它们都应服从角色人格：冷淡角色不会突然像大型犬一样扑人；怕生角色可能只会偷偷闻衣领；大胆角色可能更直接。

---

# 5. 对 {{user}} 与朋友的规则

角色可以把 {{user}} 或熟悉朋友视为“自己群体里的熟悉气味”。

但是：

- 费洛蒙不能自动把陌生人变成熟人；
- 不能自动提高好感；
- 不能强迫恋爱 / 发情 / 服从；
- 不能读取思想、判断谎言或强制认主；
- “对方身上有我的气味”不等于占有权；
- 被标记不等于恋人、伴侣、配偶或性同意。

是否愿意被贴近、嗅闻、轻蹭或梳理，仍由当下关系、人格和场景决定。

### 5.1 咩咩状态关系

MVU 与剧情只读取已有的咩咩 relationship / affinity / status。

建议表现层级：

- 陌生 / 低关系：保持距离，只能辨认气味，不主动标记；
- 熟悉 / 朋友：可能有靠近、嗅闻、轻蹭、物品气味交换；
- 高亲密：按角色自身习惯出现更明显的群体标记 / grooming；
- 成年自愿亲密关系：可使用角色专属的更亲昵版本，但仍不产生独立“费洛蒙值”。

**禁止新增 `pheromone_affinity`、`mark_level` 等第二套持久好感变量。**

---

# 6. 年龄与边界

## 6.1 `adult-consensual`

只有资料明确成年、且角色呈现无年龄争议时，才允许成人向但仍非露骨的亲昵 grooming 描述。

## 6.2 `nonsexual-only`

以下全部强制此类别：

- 未成年；
- 年龄未明且外观明显年幼；
- 资料不足无法可靠判断年龄；
- 任何不适合成人亲昵描述的角色。

这类角色的气味互动只允许：

- 同伴识别；
- 安抚；
- 拥抱 / 轻蹭；
- 衣物或毛毯留下熟悉气味；
- 非性化的动物式 grooming。

禁止色情化、发情化、性暗示式舔舐。

# 7. MVU：PHEROMONE / SCENT ARCHIVE

不新增底部第五个主导航。

在现有页面中加入两个入口：

### OPERATOR RECORDS

干员详情新增：

`PHEROMONE / 气味档案`

和 `PROFILE / ARMAMENT / STATUS` 同级作为详情子页。

显示：

- `SCENT SIGNATURE`：基础气味签名
- `INTENSITY`：强度
- `EMOTION SHIFT`：情绪变化
- `SOCIAL MARKING`：亲近 / 标记习惯
- `RELATION RESPONSE`：只读咩咩现有关系后给出的当前表现说明

### TERRA ARCHIVE / NPC

NPC详情同样增加：

`SCENT PROFILE / 气味档案`

来源是 `worldbook/npc-moe.v1.json`。

## 7.1 MVU不得保存的新状态

MVU 不保存：

- 谁标记过谁；
- 标记次数；
- 费洛蒙浓度历史；
- 独立气味好感；
- 气味所有权。

如果剧情中发生一次贴贴 / 留味，它属于普通剧情事实与关系表现，由咩咩现有状态和正文自然承接。

# 8. PRTS 悬浮窗

不把完整气味档案塞进悬浮窗。

如果当前页面已选中一名干员 / NPC，可在 PRTS PLAYER WINDOW 中仅显示一行：

`SCENT // <简短基础气味签名>`

没有选中角色时不显示。

这只是只读预览。

# 9. 静静批量生成要求

正式装配前静静应：

1. 读取463份 operator body + 现有 operator-moe；
2. 为每名干员生成独立 scent profile；
3. 把短版 `moe_append` 直接追加到现有 `moe`；
4. 生成完整 `manifest/pheromone-profile.v1.json` 供MVU查阅；
5. 对核心NPC执行同样流程，并生成 `worldbook/npc-moe.v1.json`；
6. 博士条目完成后纳入NPC流程；
7. 机械体走 mechanical 规则；
8. 年龄风险角色统一 `nonsexual-only`；
9. 不改 canonical operator/NPC 原文事实；
10. 最终做全量去重审计，禁止大批角色气味模板雷同。
