# 明日方舟角色世界书批量生产规范 v1.0

> 目标：为咩咩制卡包·全栈生成可批量、可复核、可持续扩展的角色世界书条目。
> 适配对象：现有咩咩预设；禁止修改预设本体。
> 数据入口：`reference/prts-index/catalog/index.v1.json`。

## 1. 来源优先级

1. 游戏内正式资料、官方设定、官方公开资料。
2. PRTS Wiki 当前条目，用于档案字段、身份、种族、所属、感染情况、剧情事实与人物关系核验。
3. `明日方舟剧本小说` 仅用于时间顺序、场景衔接与日期锚点辅助；与官方/PRTS冲突时以前两者为准。
4. 旧第三方角色卡、他人世界书、二创卡不得作为正文来源，只允许作为候选名称提醒。

禁止整段复制百科正文、游戏原文或第三方卡文本。所有正式条目必须重新组织与改写。

### 字段规则

- `印象`：1段，概括第一印象、气质、核心人格，不写百科式履历。
- `经历`：原则上3~5条，只保留塑造当前人格和关系网的关键事件。
- `关系`：只写会持续影响互动的关系，不做全人物关系百科。
- `心理模型`：必须保留 Trauma / Defense / Trigger / Need 四项。
- `对话范例`：3条；只模仿语气、句式与思维习惯，不复制原作长台词。
- 外观字段优先官方立绘/设定；资料未明时用非数值描述，不伪装为官方数据。

## 3. 角色触发与关键词

正式姓名作为主名；可加入官方常用别称、昵称、姓氏、称号。

推荐角色触发正则：

```regex
/<story_scene>.*?(本名|昵称|别称|称号).*?<\/story_scene>/s
```

原则：
- 不把过于泛化的单字、职业名、组织名作为单独关键词。
- 同名角色必须加入足以消歧的关键词。
- 异格/升变/不同可玩形态默认归并到同一人物主索引；只有人格或实体确实不同才拆分。

## 4. 能力条目

原生 `chara-v1` 不塞技能倍率、模组数值与整套战斗表。

对具有明确战斗/特殊能力体系的角色，与角色卡同批生成：

```text
<核心设定:角色名·能力>
定位:
武器/战斗方式:
源石技艺/特殊能力:
代表性能力:
限制与代价:
战斗习惯:
</核心设定:角色名·能力>
```

规则：
- 只写角色能做什么、怎么做、限制是什么。
- 不抄游戏技能说明，不写倍率表。
- 同名触发，与角色卡共用 `<story_scene>` 关键词。

## 5. 信息素 AU 条目

这是本卡原创 AU 层，不冒充原作设定。

全局系统使用：

```text
<核心设定:信息素系统>
定义:泰拉多数具兽类特征的种族，会产生带有个体差异的信息素与体味信号。
表现:
- 基础气味
- 情绪波动
- 种族倾向
- 亲密反应
- 抑制与中和
规则:
- 信息素不等同于强制发情
- 不得绕过角色意愿与同意
- 信息素只能影响感官与情绪倾向，不能强制决定行为
- 未成年、年龄不明或明显幼态角色不得触发成人向信息素效果
</核心设定:信息素系统>
```

明确成年且适用的角色，可另建：

```text
<核心设定:角色名·信息素>
基础气味:
强度:
种族特征:
情绪变化:
亲密状态变化:
敏感对象:
抑制方式:
特殊表现:
</核心设定:角色名·信息素>
```

信息素条目必须与角色卡分离，避免破坏 chara-v1 主体结构，也方便独立开关。

## 6. 批量生成优先级

### A类：核心/高人气角色
- 每批 5~10 人。
- 角色卡、能力条目、必要的信息素条目同批完成。
- 经历与关系允许更细，但仍控制体积。

### B类：普通干员
- 每批 20~30 人。
- 保留完整 chara-v1-arknights 字段。
- 经历、关系高度压缩。

### C类：精选剧情 NPC
- 当前只认 `story-characters.curated.index.v1.json` 中的精选池。
- 每批约 10 人。
- 已存在可玩干员形态者优先归干员池，不重复制作 NPC 卡。

## 7. QA 硬规则

每批必须依次检查：

1. **来源 QA**：名字、身份、所属、种族、感染情况、关键经历可被官方/PRTS支持。
2. **去重 QA**：干员与剧情 NPC 不重复；异格优先归并同一人物。
3. **格式 QA**：标签完整闭合；字段顺序统一；心理模型四项齐全。
4. **关键词 QA**：关键词能触发且不过度泛化。
5. **能力 QA**：不把技能倍率/游戏数值塞进角色正文。
6. **AU QA**：信息素明确标记为原创 AU；不与原作事实混写。
7. **成人边界 QA**：未成年/年龄不明/明显幼态角色只允许非性化气味或生理信号，不生成成人向亲密信息素内容。
8. **体积 QA**：普通角色避免百科式长履历；高人气角色也以可互动信息为主。
