# 《明日方舟》独立卡 {{user}} / 博士身份隔离规范 v1.0

> 本规范解决一个严重运行时错误：原作游戏以博士作为玩家视角，但本卡中的 `{{user}}` 是自定义玩家角色，**默认绝不等于博士**。

## 1. 最高优先级硬规则

`{{user}} != 博士`

这不是建议，而是本卡事实层规则。

- `{{user}}`：玩家自己的独立角色。
- `博士`：`worldbook/npcs/博士.md` 对应的原作独立 NPC。

二者可以同时存在、同时出场、互相对话。

## 2. 原作关键词归属

以下称呼在既有原作剧情 / 时间线 / 世界书中默认指向博士 NPC：

- 博士
- Doctor
- 预言家（涉及前文明身份时）
- 巴别塔的恶灵（明确指博士的语境）

禁止在材料化、正文改写、MVU展示或模型解释时自动替换为 `{{user}}`。

## 3. 不得继承的内容

除非未来由用户主动修改卡设，本卡中的 `{{user}}` 不自动继承：

- 博士的前文明人类 / 预言家身份；
- 源石计划参与经历；
- 石棺休眠与失忆历史；
- 巴别塔军事参谋经历；
- 罗德岛三大创始人身份；
- 罗德岛/PRTS的博士级权限；
- 博士的科研学历与专业知识；
- 博士与阿米娅、凯尔希、特蕾西娅、普瑞赛斯、W等人的既有原作关系；
- 原作中“博士做过的事情”；
- 博士专属对话与他人对博士的称呼。

## 4. 时间线解释规则

当 `<world_timeline>` 出现：

`博士指挥……`

含义始终是：

`博士 NPC 指挥……`

而不是 `{{user}}`。

如果当前场景同时需要玩家：

- 博士按原作事件完成博士的行为；
- `{{user}}`按玩家自己的位置、身份和信息权限参与；
- 不把博士行动强塞给 `{{user}}`；
- 不为了“玩家中心化”删除博士。

## 5. 第二人称防串台

原作素材、剧情摘要、模型生成中出现“你”时，不得仅凭“原作游戏玩家=博士”就自动判为 `{{user}}`。

判断顺序：

1. 是否明确称呼“博士”？如果是，目标=博士NPC；
2. 是否来自原作中对博士说的话？如果是，目标=博士NPC；
3. 是否是当前卡内NPC正在对玩家说话？只有此时才目标=`{{user}}`；
4. 无法确认时避免代词替换，优先写角色名。

## 6. 咩咩状态栏

`<status>` 中玩家字段仍然记录 `{{user}}`。

如需显示博士：

- 作为普通关键 NPC / 当前同行者单独列出；
- 不把博士的状态字段写进玩家栏；
- 不因博士是原作视角角色而覆盖玩家名。

## 7. MVU

- `OPERATOR RECORDS` 不把博士当干员；
- `TERRA ARCHIVE -> NPC` 中可查阅博士；
- NPC总数更新为19；
- 搜索“博士 / Doctor / 预言家”应打开博士NPC资料；
- 搜索 `{{user}}` 不得跳到博士；
- PRTS PLAYER WINDOW 的玩家状态只来自 `{{user}}` 的咩咩状态；
- 当前事件若博士在场，可作为NPC摘要另行显示，但不能覆盖PLAYER STATUS。

## 8. 世界书触发

博士角色条目的触发应围绕：

- 博士
- Doctor
- 预言家（仅高剧透上下文）

不要把 `{{user}}`、`玩家`、`U` 作为博士触发词。

同时需要避免“Doctor”出现在普通英文说明时误触发，可由静静按咩咩实际世界书触发机制采用 `<story_scene>` 范围或等价上下文约束。

## 9. 费洛蒙系统

博士作为第19名核心NPC，按 `docs/pheromone-moe-mvu-spec-v1.md` 生成独立气味签名。

博士的气味签名也只属于博士本人，不能作为 `{{user}}` 的默认气味。
