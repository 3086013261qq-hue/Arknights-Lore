# Arknights-Lore PRTS Roughcard Builder v2.6 设计冻结稿

状态：DESIGN-FROZEN / implementation pending

## 1. 目标

v2.6 将现有 PRTS 粗卡生成器升级为“文字资料 + 萌百原字段 + 官方/条目立绘视觉识别”的三源流水线。

目标不是生成最终正式角色卡，而是自动完成一张可供后续人工/AI精修的高覆盖率粗卡，并且保留每个字段的来源、冲突与原始采集材料。

原则：

1. PRTS/官方资料负责硬事实与经历、能力。
2. 萌娘百科只抓页面原字段；原字段不做语义映射。
3. 立绘视觉识别只补文字来源没有明确提供的视觉字段。
4. 原始抓取资料与生成粗卡完全分离。
5. 所有自动填充字段必须可追溯。
6. 冲突不静默覆盖，统一进入 QA。
7. 支持断点续跑，不允许全量任务中断后从头重来。
8. raw-source 与模型缓存只留本机，不提交 GitHub。

---

## 2. 面向设备

当前目标 PC：

- NVIDIA GeForce RTX 4060 Laptop GPU
- 独立显存 8 GB
- 系统内存约 16 GB
- Windows
- 项目根目录建议：`D:\Arknights-Lore`

因此 v2.6 采用“单角色、单图串行视觉识别”，禁止默认并行加载多张立绘或多个视觉模型实例。

视觉后端必须可插拔：

- `ollama`：首选易用本地后端；模型名由配置指定，不在程序内硬编码。
- `transformers`：高级本地后端，后续实现。
- `none`：仅文字抓取 + 立绘下载，不执行视觉识别。

目标模型级别：约 3B~4B 的量化多模态模型；8 GB 显存优先稳定而非追求最大模型。

## 4. 三个来源层的职责

### 4.1 PRTS / Wiki 层

负责：

- 名字
- 性别（若页面提供）
- 种族
- 职业/定位
- 所属
- 出身/出身地
- 感染情况
- 身高（若页面提供）
- 客观履历/档案资料/晋升记录等经历资料
- 特性
- 天赋
- 技能
- 能力/战斗相关短事实
- 页面分类与来源 URL

PRTS 原始结果先写入 `raw-source/prts/<角色名>/parsed.json`。

允许在“合并层”使用已经冻结的白名单字段归一，例如：

- `出身地` -> `出身`
- `矿石病感染情况` -> `感染情况`

任何新增归一规则都必须显式写入配置/代码，不允许模糊语义推断。

### 4.2 萌娘百科层

只抓原字段。

例如页面出现：

```text
发色: 银发
瞳色: 金瞳
身高: 169cm
萌点: 单马尾、兽耳、巨乳、热裤……
所属团体: ……
```

则 `fields.json` 必须保留这些字段原名和原值。

禁止：

- `萌点:单马尾` -> 自动写入 `发型`
- `萌点:巨乳` -> 自动写入 `胸部`
- `萌点:长靴` -> 自动写入 `鞋子`
- `身高` -> 自动改写成 `身材`
- 任意标签/萌点语义映射

允许“同名字段直填”：当粗卡目标字段名与萌百原字段名完全一致，且该字段尚无更高优先级明确来源时，可直接采用。

例如：

- `发色` -> `发色`
- `瞳色` -> `瞳色`
- `性别` -> `性别`（若没有更高优先级来源）

`萌点` 永远只作为原始参考资料，不直接驱动粗卡字段。

### 4.3 立绘视觉层

立绘来自 PRTS/萌百页面中可追踪到的角色图像资源。

首期只处理：

- 默认立绘
- 精英化二阶段立绘（若存在）

不默认下载所有时装，防止本地资源无限膨胀。

视觉层允许识别：

- 发色
- 发型
- 瞳色（只有图像清晰可见时）
- 身材/体型观感（中性描述）
- 上衣
- 下装
- 配饰
- 鞋子
- 可见兽耳/角/尾巴/翅膀等种族外观
- 明显携带武器或装备

视觉层禁止推断：

- 年龄
- 身高/体重数值
- 精确罩杯
- 身份、种族学名、出身、阵营
- 性格
- 隐藏在衣物下的身体细节
- 任何图片无法直接观察到的事实

`胸部`字段安全规则：

- 默认不由视觉模型输出精确罩杯。
- 明确成年角色如需要，可输出非数值、中性体型观察（如“胸部轮廓较丰满”），但正式罩杯仍留待精修。
- 未成年、年龄不明、明显年轻角色：视觉模型不得自动生成成人化胸部描述，字段保持待精修/不自动推断。

## 5. 立绘选择规则

程序不能看到一张图片就当成默认立绘。

每个候选图像保存：

```json
{
  "url": "...",
  "source_page": "...",
  "alt": "...",
  "filename": "...",
  "width": 0,
  "height": 0,
  "score_default": 0.0,
  "score_elite2": 0.0,
  "reasons": []
}
```

选择策略：

1. 使用图片周围文字、alt、文件名、链接标题、页面所在区块判定。
2. 默认立绘与精二立绘各自计算置信度。
3. 高于阈值才自动选中。
4. 低于阈值：不执行视觉合并，写入 `QA/artwork-selection.json`。
5. 不允许把时装/头像/技能图标误当立绘后继续自动填卡。

默认立绘为“基础服装”的主要视觉事实源。

精二立绘规则：

- 用于确认发色、发型、眼色、种族可见特征。
- 默认不覆盖默认立绘的上衣/下装/鞋子。
- 当默认立绘被遮挡、裁切或姿势导致局部不可见时，可作为补充来源。
- 如果精二服装与默认服装明显不同，记录为 `variant`，不覆盖基础服装。

## 6. 视觉模型输出 Schema

模型必须输出 JSON，不允许自由散文直接进入角色卡。

示例：

```json
{
  "schema_version": "vision-v1",
  "character": "能天使",
  "image_role": "default",
  "observations": {
    "发色": {"value": "...", "confidence": 0.0},
    "发型": {"value": "...", "confidence": 0.0},
    "瞳色": {"value": "...", "confidence": 0.0},
    "身材": {"value": "...", "confidence": 0.0},
    "上衣": {"value": "...", "confidence": 0.0},
    "下装": {"value": "...", "confidence": 0.0},
    "配饰": {"value": "...", "confidence": 0.0},
    "鞋子": {"value": "...", "confidence": 0.0},
    "种族外观": {"value": ["..."], "confidence": 0.0},
    "武器装备": {"value": ["..."], "confidence": 0.0}
  },
  "uncertainties": [],
  "blocked_inferences": []
}
```

置信度建议：

- `>= 0.85`：可自动补入缺失字段。
- `0.65 ~ 0.84`：写入候选，但进入低置信 QA，不自动进入最终粗卡或在字段后标注需复核。
- `< 0.65`：只保留 raw vision，不用于粗卡。

最终阈值在首批 5 人压力测试后冻结。

## 7. 字段合并优先级

### 7.1 核心事实字段

优先级：

1. PRTS/官方明确结构化事实
2. 萌百同名原字段
3. 保持待精修

视觉模型不得覆盖核心事实字段。

### 7.2 视觉字段

目标字段：

- 发色
- 发型
- 瞳色
- 身材
- 胸部
- 上衣
- 下装
- 配饰
- 鞋子

优先级：

1. PRTS/官方明确文字字段（若存在）
2. 萌百完全同名原字段
3. 默认立绘高置信视觉观察
4. 精二立绘仅用于补缺/确认
5. 待精修

注意：萌百 `萌点` 不参与自动合并。

### 7.3 冲突处理

若不同来源给出不一致值：

- 不静默覆盖。
- 保留所有候选值与来源。
- 写入 `QA/conflicts.json`。
- 粗卡采用最高优先级明确来源；若优先级相同或不确定，则字段标记为待复核。

## 8. Provenance 字段来源追踪

每张角色粗卡对应：

`build/rough-worldbook/provenance/<角色名>.json`

示例：

```json
{
  "character": "能天使",
  "fields": {
    "种族": {
      "value": "萨科塔",
      "source": "prts",
      "source_field": "种族",
      "confidence": 1.0
    },
    "发色": {
      "value": "...",
      "source": "moegirl",
      "source_field": "发色",
      "confidence": 1.0
    },
    "鞋子": {
      "value": "...",
      "source": "vision:default",
      "confidence": 0.91,
      "image_sha256": "..."
    }
  },
  "conflicts": []
}
```

正式精修时可以快速判断哪些字段是硬事实、百科原字段或视觉推断。

## 9. 断点与任务状态

全量约数百名角色，视觉识别耗时显著，必须支持断点续跑。

每个角色分阶段状态：

```text
pending
text_prts_done
text_moegirl_done
artwork_done
vision_default_done
vision_elite2_done
merge_done
qa_done
complete
failed
```

`raw-source/run-state/state.json` 保存状态。

默认行为：

- 已完成步骤跳过。
- 已下载且 SHA256 匹配的资源不重复下载。
- 已识别图像且模型版本、prompt版本、图片 SHA 未变化，不重复识图。
- 单个角色失败不终止全量任务；记录后继续下一角色。
- 提供“仅重跑失败项”。

## 10. 本地资源与缓存策略

所有大文件默认落到项目 D 盘：

```text
D:\Arknights-Lore\.cache\
D:\Arknights-Lore\.models\
D:\Arknights-Lore\raw-source\
```

环境变量/后端缓存也尽可能指向 `.models` 或 `.cache`，避免模型和图片缓存写入 C 盘用户目录。

每完成一个角色：

1. 保存视觉 JSON。
2. 释放图像对象。
3. 提示后端释放可释放的推理资源。
4. 才处理下一角色。

不默认并发视觉推理。

## 11. PC 启动菜单设计

Windows BAT 只做入口，不承载中文业务逻辑，避免此前 cmd 编码问题。

建议菜单：

```text
1 = 富资料测试（能天使 / 银灰 / 塞雷娅 / 斯卡蒂 / 莫斯提马）
2 = 文字双源测试（不下载/识图立绘）
3 = 立绘下载 + 视觉测试（仅上述5人）
4 = 全量角色：文字 + 立绘 + 视觉 + 粗卡
5 = 继续上次中断任务
6 = 仅重跑失败项
7 = 仅重新生成粗卡（使用现有 raw-source，不联网）
8 = 检查环境/显卡/视觉后端
```

首次使用全量模式前必须先通过模式 1 或 3。

## 12. 首批验收对象

固定 5 人：

- 能天使
- 银灰
- 塞雷娅
- 斯卡蒂
- 莫斯提马

原因：组织、种族、服装、武器和资料丰富度差异较大，适合压力测试。

验收项目：

1. PRTS 核心字段拆分正确。
2. PRTS 经历/能力有有效粗采集。
3. 萌百原字段完整保存，且未发生语义映射。
4. 默认立绘与精二立绘选择正确。
5. 视觉 JSON 为严格 schema。
6. 视觉字段没有覆盖高优先级文字事实。
7. 默认服装没有被精二/时装覆盖。
8. provenance 可追溯。
9. conflict / low-confidence QA 正常。
10. 中断后可继续。
11. 模型与 raw-source 均落在 D 盘项目目录。

只有 5 人测试通过，才允许启动 463 干员 + 精选 NPC 的角色全量。

## 13. 与正式角色卡的边界

v2.6 粗卡仍然不是正式角色卡。

程序自动处理：

- 基础事实
- 经历素材
- 能力素材
- 百科原字段
- 视觉外貌素材
- 来源追踪

后续人工/AI精修负责：

- 印象
- 关系整理
- 心理模型
- 三条原创对话范例
- 经历的高质量重写与去冗余
- 战斗方式/能力的最终总结
- 胸部具体罩杯（仅在项目规则允许且角色成年边界明确时人工处理）
- 信息素 AU（仅符合年龄与规则的角色）
- 世界书关键词与正则
- 最终 QA

不得把 raw-source、网页原文、自动视觉结果直接作为正式远程运行时资源。

## 14. 实现顺序

### Phase A — 数据与目录层

- raw-source 目录
- run-state
- provenance
- QA 输出
- 缓存 D 盘化

### Phase B — 文字双源

- 修复 PRTS 字段切分
- 萌百原字段抓取
- 同名字段直填
- 不做萌点语义映射

### Phase C — 立绘层

- 候选图发现
- 默认/精二评分
- 下载与 SHA256
- 错误/低置信 QA

### Phase D — 视觉层

- vision backend 抽象
- 严格 JSON schema
- 默认/精二分别识别
- 视觉结果合并

### Phase E — 粗卡合并

- 字段优先级
- provenance
- conflict QA
- 5 人压力测试

### Phase F — 全量

5 人验收通过后才开放全量菜单。

## 15. 冻结结论

v2.6 的核心不是“让视觉模型替我们写角色卡”，而是建立一条可复核、可断点、可追溯的资料生产线：

```text
PRTS/官方事实
        +
萌百原字段（不语义映射）
        +
默认/精二立绘视觉观察
        ↓
来源可追溯的高覆盖率粗卡
        ↓
人工/AI精修
        ↓
咩咩全栈正式角色世界书
```

本设计稿通过后，后续实现不得绕过这里冻结的来源边界、萌百不映射原则、视觉补缺原则、默认立绘服装优先原则、成人边界、raw-source 本地隔离与 provenance 追踪。
